# Review of current.kt

## Concrete defects

1. **The Open finder is ambiguous.** `DraftActions` exposes two buttons named `Open`, under `draft` and `archive`. A singular `onNodeWithText("Open")` requires exactly one match; it does not choose the draft. Both the click and the later existence assertion are ambiguous. Selecting index zero would merely make the test depend on layout order. The replacement scopes the action by the draft ancestor and checks `Draft opened`, with `Archive opened` absent.
2. **The assertions do not prove either action worked.** Finding `Open` after clicking it says nothing about the displayed callback result. Finding `Send` after clicking it says nothing about sending or delivery. Both controls can remain present when their handlers are broken. The replacement asserts the actual draft result and the message's pending-to-receipt transition.
3. **Send starts disabled.** `MessagePanel` requires nonblank input, but the snippet never types anything. Clicking the disabled button cannot start the intended request. The replacement checks the disabled initial state, enters a concrete message into the editable semantics node, and checks that Send becomes enabled before clicking.
4. **The receipt has no producer.** The snippet creates a deferred and awaits it in the fake but never completes it. Even after fixing input, the panel would remain pending. `waitForIdle()` synchronizes known UI work; it does not resolve a parked sender. The replacement deliberately holds the deferred pending, checks `Sending` and disabled Send, then explicitly supplies a receipt and asserts that receipt is displayed and pending labels disappear.
5. **The sleep is both wasteful and the wrong synchronization mechanism.** A one-second wall-clock sleep cannot fix duplicate selectors, enable Send, or complete the deferred. Compose's composition-owned one-second long-wait effect belongs to Compose virtual time, not this sleep. The replacement uses normal v2 rule synchronization and a controlled deferred. It does not assert the timing of `Still sending`; that would require a separate clock-controlled test establishing the timer start and advancing `mainClock`.
6. **The mounted siblings lack a layout owner.** Calling `DraftActions`, `Text`, and `MessagePanel` as sibling content without a surrounding layout can overlap their UI. The replacement separates the independent behaviors into two focused tests and puts the draft actions and displayed result in a `Column`.
7. **Pending work needs failure-path ownership.** The original never releases its deferred. The rule disposes composition-owned coroutine scopes, but the replacement also cancels its test-owned deferred in `finally`, including when an assertion fails. All fake state and request history are fresh per method; no global dispatcher replacement is needed.
